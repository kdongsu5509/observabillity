## 조사하면서 확인한 것

- **Tempo 3.x 구조 변경** : 아키텍처 문서의 구성요소가 Distributor, Kafka, Block-builder, Live-store, Query frontend, Querier, Compaction, Metrics-generator로 바뀌었어요(이전의 ingester 대신 live-store · block-builder). "Migrate to 3.0"과 "Deployment modes" 문서로 우리 단일 바이너리 구성이 내부적으로 어떻게 동작하는지 9장에서 확인해야 해요.
- **Prometheus 내부 구조** : Grafana 문서에는 "What is Prometheus?"와 데이터소스 문서까지만 있어요. 7장의 TSDB · 실행 플래그 설명은 출처 B에 따라 `prometheus.io`를 써야 해요.
- **Grafana 백업** : `administration/back-up-grafana/` 문서가 있어요. `grafana.db` 백업(남은 일)을 16장에서 이 문서로 다룰 수 있어요.
- **k6 → Prometheus** : `results-output/real-time/prometheus-remote-write/`와 `results-output/grafana-dashboards/`가 있어 비비디 Prometheus·Grafana에 바로 붙일 수 있어요.
- **Loki 단일 바이너리 모니터링** : `operations/meta-monitoring/single-binary/` 문서가 우리 구성(단일 바이너리)과 정확히 맞아요.
